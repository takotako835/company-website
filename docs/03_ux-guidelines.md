# 03. UXガイドライン(UXデザイナー観点)

コーポレートサイトのUXは「訪問者の疑問に、訪問者の順番で答えること」。
自社が言いたい順ではなく、ユーザーが知りたい順に情報を並べる。

## 1. 設計原則

1. **3秒ルール**: ファーストビューだけで「何の会社か」「誰向けか」「次に何をすべきか」が分かる
2. **1ページ1ゴール**: 各ページの最重要アクションを1つ定め、それ以外の導線は控えめにする
3. **不安の先回り**: 発注・応募をためらう理由(実績は?費用感は?返信は来る?)にページ内で答える
4. **迷子を作らない**: どのページからも2クリック以内で問い合わせに到達できる

## 2. ユーザーの来訪シナリオ(導線設計の基準)

### シナリオA: 発注検討者(最重要)
```
検索/紹介 → トップ → サービス → 実績・会社概要(信頼確認) → 問い合わせ
```
- トップのHero直下に「サービス概要」と「実績・数字」を置く
- 問い合わせボタンは全ページのヘッダー右端に固定表示

### シナリオB: 求職者
```
求人媒体 → 採用ページ → 会社概要・代表メッセージ → エントリー
```
- 採用ページから会社の雰囲気が分かるコンテンツへ回遊できるようにする

### シナリオC: 既存取引先・金融機関(信頼確認)
```
社名検索 → トップ → 会社概要(所在地・沿革・役員)
```
- 会社概要は情報の正確さと見つけやすさを最優先。凝った演出は不要

## 3. ナビゲーション

- グローバルナビは **5項目以内**(例: サービス / 実績 / 会社概要 / 採用 / お知らせ)+ CTA ボタン
- 現在地をナビ上で明示(下線 or 色)
- SPはハンバーガーメニュー。開閉は0.25s以内、メニュー内にもCTAを置く
- フッターに全ページへのリンク + 住所・電話番号を記載(信頼要素)
- パンくずリストを下層ページ全てに設置

## 4. ページ骨格の型

### トップページ
1. Hero: 一文の価値提案 + サブコピー + CTA
2. 事業・サービス概要(3カード程度)
3. 選ばれる理由 / 数字で見る実績
4. 導入事例・お客様の声(あれば)
5. お知らせ(最新3件)
6. 問い合わせ誘導セクション(CTA再掲)

### 下層ページ共通
- ページ上部: H1 + このページで分かることの要約(1〜2文)
- ページ末尾: 次のアクションへの誘導(問い合わせ or 関連ページ)

## 5. フォームUX(CVの生命線)

- 項目は最小限: 会社名 / 氏名 / メール / 問い合わせ内容(電話番号は任意)
- 必須/任意をラベルに明記(必須だけに「必須」バッジ)
- エラーは送信時ではなく入力時にフィールド直下へ日本語で表示
- 送信ボタンの文言は具体的に:「送信する」ではなく「この内容で問い合わせる」
- 送信後: 完了ページで「◯営業日以内に返信」と明記(不安の解消)
- 入力途中のデータをページ遷移で失わせない

## 6. アクセシビリティ基準(WCAG 2.1 AA 準拠・必須)

- すべての機能がキーボードのみで操作可能(Tab順序が視覚順と一致)
- フォーカスリングを消さない(`outline: none` 単独使用の禁止)
- 画像に適切な `alt`(装飾画像は `alt=""`)
- フォーム: `<label>` を必ず関連付け、エラーは `aria-describedby` で通知
- 見出しレベルを飛ばさない(h1→h3 禁止)
- ハンバーガーメニュー: `aria-expanded` / `aria-label` を付与
- 色だけで情報を伝えない(エラーは色 + アイコン + テキスト)

## 7. モバイル最優先

- 実装・確認は 375px 幅から始める(モバイルファースト)
- タップターゲット 44×44px 以上、隣接要素と8px以上の間隔
- 電話番号は `tel:` リンクにする(SPからの問い合わせ導線)
- 固定ヘッダーはSPで高さ 56〜64px に抑える

## 8. 状態設計を忘れない

- お知らせ0件時の空状態、フォーム送信中のローディング、送信失敗時の表示をすべて定義してから実装する
