# 04. コピーライティングガイド(コピーライター観点)

コーポレートサイトの文章は「読ませる」のではなく「一瞬で伝わる」ことが仕事。
形容詞を削り、事実と具体で語る。

## 1. 原則

1. **具体 > 抽象**: 「高品質なサービス」ではなく「納品後1年間、無償で不具合対応」
2. **相手主語**: 「私たちは◯◯できます」より「◯◯にお困りの方へ」
3. **1文1義**: 一文は50字以内を目安。読点で文を繋ぎ続けない
4. **数字で語る**: 実績・年数・件数など検証可能な数字を優先(**実在しない数字の創作は絶対禁止**)
5. **盛らない**: 「業界No.1」「圧倒的」などの根拠のない最上級表現は使わない(景表法リスクも回避)

## 2. 見出し(コピー)の書き方

### Heroコピーの型(いずれかで3案以上出して選ぶ)
- 価値提案型: 「{{顧客の課題}}を、{{手段}}で解決する」
- 宣言型: 「{{自社の信念を短く}}」
- 顧客ベネフィット型: 「{{顧客が得られる未来}}」

### 良い例 / 悪い例
| ❌ 悪い | ✅ 良い | 理由 |
|---|---|---|
| 最先端の技術で未来を創造します | 製造業の生産管理を、20年つくり続けてきました | 具体性・検証可能性 |
| 高品質・低価格・スピード対応 | 要件定義から運用まで、担当が変わらず伴走します | 全部盛りは何も伝えない |
| Solutions for your business | 在庫のズレを、現場のせいにしないシステムを | 英語かぶれより顧客の言葉 |

## 3. トーン & マナー

- 文体: です・ます調で統一(体言止めは見出しのみ可)
- 人称: 自社は「当社」または「私たち」に統一({{どちらかに決める}})
- 顧客の呼称: 「お客様」に統一
- 漢字/ひらがなの開き方:
  - 開く: 「出来る→できる」「頂く→いただく」「更に→さらに」「事→こと」「様々→さまざま」
  - 閉じる: 「わたしたち→私たち」
- 英数字: 半角。単位や固有名詞以外のカタカナ語の乱用を避ける
  (ソリューション → 解決策 / コミット → 約束、など言い換えを検討)

## 3b. 改行・段落のルール(2026年8月27日 追加)

- **文の途中では改行しない**。読点や助詞のあとで `<br>` を入れない
- **段落は話題が変わるところだけで分ける**。リズムを作るためだけに分割しない
- **箇条書きは1項目を1行に**。1つの項目に複数の文を詰め込まない
- **スマホの見た目のためだけに `<br>` を使わない**。折り返しはCSSに任せる
  (`word-break: auto-phrase` を全体に指定済み。詳細は 02_design-system.md)
- **見出しの直後に余計な空きを作らない**。見出し下の余白は 24px(SP)/ 32px(PC)で統一
- `<br>` を使ってよいのは次の場合のみ:
  - 標語・キーコピーを意図した行組みで見せるとき(会社案内の締め、経営理念など)
  - 社名と役職のように、別々の項目を並べるとき(可能なら要素を分ける方が望ましい)

## 4. 表記統一ルール

- 「!」は原則使用しない(採用ページのみ最小限可)
- 三点リーダは「…」(2つ重ねない)
- 括弧は全角「」()を使用
- 日付: 「2026年8月27日」形式
- 会社名の初出はフルネーム、以降は略称可

## 5. ページ別の文章方針

| ページ | 目的 | 文章の重心 |
|---|---|---|
| トップ | 3秒で理解させ、下層へ送る | 短く・具体的に。各セクション見出し+2文まで |
| サービス | 検討材料を渡す | 課題→解決→提供範囲→流れ→(費用感)。FAQで不安に先回り |
| 会社概要 | 信頼の裏付け | 事実を正確に。代表メッセージは自慢話でなく「なぜやるか」 |
| 採用 | 合う人に刺さる | きれいごとを並べず、大変さも正直に書く |
| お問い合わせ | 心理的ハードルを下げる | 「◯営業日以内に返信」「営業目的の連絡はしません」等の安心情報 |

## 6. CTA(ボタン文言)

- 抽象的な「詳しくはこちら」を避け、行き先が分かる文言に:
  - 「サービスの詳細を見る」「導入事例を読む」「相談してみる(無料)」
- 問い合わせCTAには心理的ハードルを下げる添え書きを付ける:
  - 例: 「まだ検討段階でも構いません」

## 7. 執筆ワークフロー(Claude Codeへの指示)

1. `docs/content/` の該当ファイルの構成に沿って起草する
2. 見出しコピーは必ず3案提示し、ユーザーに選んでもらう
3. 事実(数字・実績・沿革)は `{{ }}` プレースホルダのままにし、勝手に埋めない
4. 起草後、このガイドの表記ルールでセルフチェックしてから提出する
